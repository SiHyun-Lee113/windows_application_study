# Windows 네이티브 개발 학습 과정

## 학습 목표

- Flutter 개발 경험을 바탕으로 C++과 Windows 네이티브 개발에 필요한 기반 지식을 쌓는다.
- 메모리, 객체 수명, 소유권을 이해하고 C++ 코드를 직접 구현·디버깅한다.
- Windows 네이티브 API를 읽고 활용하며 오류와 자원을 올바르게 처리한다.
- UI, 백그라운드 작업, 테스트, 배포를 포함하는 Windows 애플리케이션을 완성한다.

## 현재 진행 상태

- 마지막 갱신: 2026-10-14
- 현재 단계: **1-1. 개발 환경 확인과 첫 C++ 프로그램 — 진행 중**
- 확인된 배경: Flutter 개발 경험이 있음. 작업 PC는 Windows, 자택 PC는 macOS. C++과 Windows 개발의 구체적인 이해 수준은 아직 확인하지 않음.
- 확인된 Windows 도구: Visual Studio Community 2022, MSVC, Windows SDK. 이번 예제는 C++17과 MSVC로 진행함. Mac의 도구 설치 상태는 아직 확인하지 않음.
- 완료한 학습·실습: 사용자가 Developer PowerShell에서 MSVC로 첫 예제를 빌드·실행한 로그를 제출함. `Hello, C++!`와 `Lesson: 1` 출력을 확인함. 재빌드 비교와 디버거 실습은 아직 확인하지 않음.
- 현재 과제: **Visual Studio에서 실행·중단점·변수 관찰, 소스 수정 전후의 재빌드 결과 비교**

## 1단계. C++ 기초와 개발 도구

**목표:** 코드를 작성하고 빌드·실행·디버깅하는 과정을 이해한다.

- [ ] **1-1. 개발 환경 확인과 첫 프로그램**: 설치된 IDE·컴파일러·Windows SDK를 확인하고 사용할 C++ 표준과 빌드 방법을 정한다. 콘솔 출력, 중단점, 변수 관찰을 실습한다.
- [ ] **1-2. 타입과 제어 흐름**: 기본 타입, 초기화, 타입 변환, 조건문, 반복문, 입력·출력을 학습한다. Dart의 타입과 비교한다.
- [ ] **1-3. 함수와 클래스**: 함수 인자와 반환값, 값 전달, 클래스와 접근 제어를 학습한다. 작은 계산기 또는 항목 관리 프로그램을 만든다.
- [ ] **1-4. 빌드 구조**: 헤더·소스 파일, 선언·정의, 컴파일·링크를 학습한다. 의도적인 컴파일 오류와 링크 오류를 구분하고 해결한다.

**단계 실습:** 프로그램을 여러 헤더·소스 파일로 나누고, 새로운 기능 하나를 추가한다.

**완료 기준:** 직접 빌드·실행할 수 있고, 디버거로 실행 흐름을 확인하며 컴파일 오류와 링크 오류의 차이를 설명할 수 있다.

## 2단계. 메모리와 객체 수명

**목표:** 값이 어디에 존재하고, 누가 소유하며, 언제 정리되는지 설명한다.

- [ ] **2-1. 메모리와 접근**: 지역 변수의 수명, 스택·힙, 포인터·참조, `nullptr`, `const`를 학습한다. 함수 인자 전달 방식에 따른 차이를 관찰한다.
- [ ] **2-2. 생성과 소멸**: 생성자·소멸자, 스코프, RAII(Resource Acquisition Is Initialization)를 학습한다. Dart의 GC와 비교하고, 조기 반환에서도 자원이 정리되는지 확인한다.
- [ ] **2-3. 소유권과 스마트 포인터**: `std::unique_ptr`, `std::shared_ptr`, `std::weak_ptr`의 사용 목적을 구분한다. 비소유 포인터·참조의 수명 조건과 순환 참조를 다룬다.
- [ ] **2-4. 복사와 이동**: 복사·이동 의미론, `std::move`, Rule of Zero를 학습한다. 값 전달과 이동 후 객체의 사용 조건을 확인한다.

**단계 실습:** 작은 자원 관리 예제에서 소유자와 해제 시점을 표시하고, 수동 정리 코드를 RAII 방식으로 바꾼다.

**완료 기준:** 객체 수명, 누수, 댕글링 포인터의 원인을 설명하고, 단독 소유와 공유 소유에 맞는 방식을 선택할 수 있다.

## 3단계. 현대 C++와 표준 라이브러리

**목표:** 표준 라이브러리로 데이터와 오류를 다루는 실용적인 코드를 작성한다.

- [ ] **3-1. 문자열과 컨테이너**: `std::string`, `std::vector`, `std::map`, `std::unordered_map`을 학습한다. Dart의 String·List·Map과 비교하고 복사 비용과 참조 무효화를 다룬다.
- [ ] **3-2. 반복자와 알고리즘**: 범위 기반 반복문, 검색·정렬 알고리즘, 람다를 사용해 항목 목록을 처리한다.
- [ ] **3-3. 템플릿 기초**: 타입에 따라 재사용되는 함수와 클래스를 읽고 작은 함수 템플릿을 작성한다.
- [ ] **3-4. 오류와 파일 처리**: 예외, 오류 코드, `std::optional`의 목적을 구분한다. 파일 입출력과 `std::filesystem`을 실습한다.

**단계 실습:** 항목을 검색·정렬하고 파일에 저장·복원하는 콘솔 도구를 만든다. 잘못된 입력과 파일 접근 실패를 처리한다.

**완료 기준:** 적절한 컨테이너와 알고리즘을 선택하고, 정상 경로와 실패 경로를 재현하며 처리 결과를 설명할 수 있다.

## 4단계. Windows와 Win32 기초

**목표:** Windows 창과 이벤트가 동작하는 구조를 이해한다.

- [ ] **4-1. 운영체제 기본 개념**: 프로세스, 스레드, 가상 메모리, 핸들을 학습한다. 포인터와 핸들의 차이를 설명한다.
- [ ] **4-2. 문자열과 Win32 타입**: Windows의 UTF-16 문자열, UTF-8과의 변환 경계, 주요 Win32 타입과 Unicode API 사용을 학습한다.
- [ ] **4-3. 창과 메시지 루프**: 진입점, 창 클래스 등록, 창 생성, 메시지 루프, 윈도우 프로시저를 연결해 첫 창을 만든다.
- [ ] **4-4. 입력과 화면 갱신**: 주요 메시지, 키보드·마우스 입력, 창 크기 변경, 기본 그리기와 컨트롤 이벤트를 처리한다. Flutter의 이벤트 처리와 비교한다.

**단계 실습:** 버튼이나 입력에 반응하고 창 크기 변경을 처리하는 작은 Win32 프로그램을 만든다.

**완료 기준:** 창 생성부터 종료까지의 흐름을 설명하고, 특정 입력이 어떤 메시지와 처리 코드로 이어지는지 추적할 수 있다.

## 5단계. 네이티브 API와 동시성

**목표:** API 계약을 읽고 Windows 자원과 백그라운드 작업을 안전하게 관리한다.

- [ ] **5-1. API 문서와 오류 진단**: 인자, 반환값, 실패 조건, 자원 해제 요구 사항을 문서에서 찾는다. 해당 API가 규정한 방식으로 오류를 확인하고 `GetLastError` 사용 시점을 학습한다.
- [ ] **5-2. 파일·디렉터리·시스템 정보**: 디렉터리 탐색, 파일 열기·읽기·쓰기, 시스템 정보 조회를 실습한다. 핸들과 탐색 자원을 올바른 정리 함수로 해제한다.
- [ ] **5-3. 프로세스와 스레드**: 프로세스 생성, 대기, 스레드 실행과 수명을 학습한다. C++ 표준 스레드 도구와 Windows API의 역할을 구분한다.
- [ ] **5-4. 동기화와 UI 응답성**: 공유 데이터, 경쟁 상태, 뮤텍스, 작업 취소, 종료를 학습한다. 작업 결과를 UI 스레드로 전달한다.

**단계 실습:** 파일 정보를 수집하는 작업을 구현하고, 접근 실패·취소·작업 중 종료를 확인한다. API의 실패 조건과 자원 정리를 설명한다.

**완료 기준:** API 문서를 근거로 구현하고, 실패 경로에서도 자원이 정리되며, 작업 스레드와 UI 스레드의 책임을 구분할 수 있다.

## 6단계. Windows 애플리케이션 완성

**목표:** 앞서 배운 내용을 연결해 작은 데스크톱 앱을 완성한다.

**기본 프로젝트:** 폴더 경로를 입력해 파일 목록과 기본 정보를 조회하는 Win32 애플리케이션.

- [ ] **6-1. 요구 사항과 구조**: 경로 입력, 조회, 목록 표시, 오류 안내, 취소 동작을 정리한다. UI 코드와 파일 조회 로직을 분리한다.
- [ ] **6-2. 기본 기능 구현**: 정상적인 폴더 조회와 결과 표시를 먼저 완성한다. 문자열과 자원의 소유권을 정리한다.
- [ ] **6-3. 응답성과 안정성**: 백그라운드 조회, 진행 상태, 취소를 구현한다. 존재하지 않는 경로, 접근 실패, 한글 경로, 반복 조회, 조회 중 종료를 확인한다.
- [ ] **6-4. 검증과 배포**: 핵심 로직에 필요한 테스트를 작성하고 디버거로 문제를 분석한다. Release 빌드, 실행에 필요한 구성 요소, 빌드·실행 설명을 정리한다.

**완료 기준:** 문서의 명령으로 앱을 빌드·실행할 수 있고, 정상·오류·취소·종료 동작을 검증하며, 구조와 자원 수명 관리 방식을 설명할 수 있다.

## 7단계. 선택 심화

**목표:** 기본 과정을 마친 뒤 관심 분야와 프로젝트 요구에 맞는 역량을 확장한다.

- [ ] **7-1. COM 기초**: 인터페이스, 참조 카운팅, 초기화, `HRESULT`를 학습하고 작은 COM API 사용 예제를 만든다.
- [ ] **7-2. DLL과 호출 경계**: 정적·동적 링크, DLL 내보내기·불러오기, ABI와 경계에서의 메모리 소유권을 학습한다.
- [ ] **7-3. C++/WinRT와 Windows UI 기술**: 기본 앱의 요구와 개발 환경을 바탕으로 학습할 기술을 선택하고 작은 화면을 구현한다.
- [ ] **7-4. Flutter와 네이티브 연동**: 기존 Flutter 경험을 활용해 네이티브 기능 호출, 데이터 전달, 스레드와 자원 관리를 연결한다.

**완료 기준:** 선택한 주제의 예제를 직접 구현하고, 호출 경계와 수명·오류 처리 방식을 설명할 수 있다. 모든 심화 회차를 필수로 완료할 필요는 없다.

- 어려웠던 개념 / 보충할 내용: 사용자가 Visual Studio 실행 시점, VS Code로 빌드 가능한지, 두 도구의 차이와 사용 시기를 질문함. IDE·편집기·컴파일러 역할과 Visual Studio 실행·디버깅 방법을 보충함.
- 강사의 빌드·실행 검증: Developer PowerShell 환경을 초기화하고 `lessons/01-hello/build`에서 `cl /nologo /EHsc /std:c++17 /W4 /Zi /Od ..\main.cpp /Fe:hello.exe` 실행 — 빌드 성공. 이어서 `.\hello.exe` 실행 — `Hello, C++!`와 `Lesson: 1` 출력, 종료 코드 0. 사용자 실습 완료를 의미하지 않음.
- Visual Studio 프로젝트 검증: `lessons/01-hello`에서 `MSBuild.exe hello.vcxproj /t:Build /p:Configuration=Debug /p:Platform=x64 /nologo /verbosity:minimal` 실행 — 빌드 성공. `build/vs/x64/Debug/hello.exe` 실행 — 예상 출력 일치, 종료 코드 0. 디버깅용 `hello.pdb` 생성 확인. 첫 검증은 검증용 셸의 `PATH`/`Path` 중복으로 실패했으며, 검증 프로세스에 전달하는 환경 변수 이름을 통일해 재실행함. 시스템·사용자 환경 변수는 변경하지 않음.
- 미실행 검증: 사용자의 Visual Studio 직접 조작, 디버거 변수 관찰, 재빌드 전후 비교는 아직 확인하지 않음. Mac 실행은 현재 Windows 환경에서 확인할 수 없음.
