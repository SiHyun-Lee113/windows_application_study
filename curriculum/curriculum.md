# Windows 네이티브 개발 학습 과정

## 학습 목표

- Flutter 개발 경험을 바탕으로 C++과 Windows 네이티브 개발에 필요한 기반 지식을 쌓는다.
- 메모리, 객체 수명, 소유권을 이해하고 C++ 코드를 직접 구현·디버깅한다.
- Windows 네이티브 API를 읽고 활용하며 오류와 자원을 올바르게 처리한다.
- UI, 백그라운드 작업, 테스트, 배포를 포함하는 Windows 애플리케이션을 완성한다.

## 2026-10-15 학습 요약

- 타입·변환: int / int는 정수 몫을 구함. 실수 몫이 필요하면 나누기 전에 형변환함. 중괄호 초기화는 축소 변환을 제한함.
- 주소·접근: &value는 주소를 구하고 *p는 포인터가 가리키는 객체에 접근함. 선언의 int&와 int*는 각각 참조와 포인터 타입을 나타냄.
- 참조·포인터: 참조는 기존 객체의 별칭이며 연결 대상을 바꿀 수 없음. 일반 포인터는 저장 주소를 바꿀 수 있고, *p에 대입하면 가리키는 객체의 값을 변경함.
- const: const int*는 포인터를 통한 정수 값 변경을 금지하고 int* const는 저장 주소 변경을 금지함. const int&는 읽기 전용 별칭이며, 변경 가능한 원본이 다른 경로로 바뀌면 그 값을 읽음.
- 반환·수명: int 값 반환은 호출부의 별도 변수를 초기화하므로 함수 내부 지역 변수의 수명 종료와 독립적임. 수명이 끝난 지역 객체의 주소·참조를 통해 그 값을 읽으면 안전하지 않음.
- 소멸자: 일반 지역 객체는 선언된 블록을 벗어날 때 자동 소멸함. return 과정에서도 소멸자가 호출되며 반환값 저장 여부와 무관함. 마지막 S5의 ADB 출력과 이유를 정확히 설명함.
- 금일 종료: 객체 소멸자까지. 다음 수업은 RAII 개념과 06-raii 파일 실습부터 시작하며, RAII는 사용자 미진행 상태임.

## 2단계. 메모리와 객체 수명

**목표:** 값이 어디에 존재하고, 누가 소유하며, 언제 정리되는지 설명한다.

- [ ] **2-1. 메모리와 접근**: 지역 변수의 수명, 스택·힙, 포인터·참조, `nullptr`, `const`를 학습한다. 함수 인자 전달 방식에 따른 차이를 관찰한다.
- [ ] **2-2. 생성과 소멸**: 생성자·소멸자, 스코프, RAII(Resource Acquisition Is Initialization)를 학습한다. Dart의 GC와 비교하고, 조기 반환에서도 자원이 정리되는지 확인한다.
- [ ] **2-3. 소유권과 스마트 포인터**: `std::unique_ptr`, `std::shared_ptr`, `std::weak_ptr`의 사용 목적을 구분한다. 비소유 포인터·참조의 수명 조건과 순환 참조를 다룬다.
- [ ] **2-4. 복사와 이동**: 복사·이동 의미론, `std::move`, Rule of Zero를 학습한다. 값 전달과 이동 후 객체의 사용 조건을 확인한다.

**단계 실습:** 작은 자원 관리 예제에서 소유자와 해제 시점을 표시하고, 수동 정리 코드를 RAII 방식으로 바꾼다.

### 2026-10-15 — &와 * 용법 보충

- 사용자 요청: &와 *의 의미를 정확히 모른다고 밝히고, 설명을 들은 뒤 기존 확인 문제를 다시 풀겠다고 함.

- 용법 1: `int& r = n;`의 &는 참조 선언 문법으로 r을 n의 별칭으로 선언함. 주소를 구하는 연산과 구분함.
- 용법 2: `int* p = &n;`에서 선언 부분의 *는 p를 int 포인터로 선언하는 문법임.
- 용법 3: 표현식 `&n`은 n의 주소를 구하고 결과는 int* 타입의 포인터임. 참조 별칭 r에 대해 &r은 &n과 같은 객체의 주소임.
- 용법 4: 표현식 `*p`는 포인터가 가리키는 객체에 접근하는 역참조임. 읽기와 쓰기 모두 가능하며 `*p = 20;`은 이 예제에서 n의 값을 바꿈.
- 보충 예제: n=10, p=&n, r=n 별칭으로 시작해 *p=20 후 r=30을 수행하면 n·r·*p로 읽는 값은 모두 30임. p는 계속 n의 주소를 보관함. 객체의 값과 주소를 구분해 설명함.

- 이해 확인: 아직 미확인. 강사의 해설을 제공한 것만으로 습득으로 처리하지 않음.

- 평가: 출력과 이유 모두 정확함. 이 사례에서 지역 객체 소멸은 호출부의 변수 저장 여부가 아니라 함수 종료에 연결된다는 점을 확인함. 같은 출력 예측 문제는 줄이고 자원 정리의 실제 활용으로 진행함.
- RAII 예제: [main.cpp](../lessons/06-raii/main.cpp), [Visual Studio 프로젝트](../lessons/06-raii/raii.vcxproj)를 추가함. writeNote에서 지역 std::ofstream 객체 file로 note.txt를 열고 Learning RAII 한 줄을 쓴 뒤 0을 반환함. 열기 실패는 1로 반환하고 main에서 결과를 출력함.
- 설명 범위: std::ofstream은 파일 출력 스트림 객체임. 열린 파일의 정리는 객체 소멸 과정에서 내부 파일 버퍼를 통해 이루어짐. 정상적인 함수 종료 시 수동 close 호출 없이도 파일을 닫는 책임을 객체 수명에 묶는 점을 설명함. 파일 닫기와 파일 삭제는 다름.
- 근거: [Microsoft Learn basic_ofstream](https://learn.microsoft.com/en-us/cpp/standard-library/basic-ofstream-class?view=msvc-170), [C++17 파일 버퍼 소멸자 규칙](https://timsong-cpp.github.io/cppwp/n4659/filebuf.cons#5)을 확인함.
- 강사 빌드 명령: lessons/06-raii에서 MSBuild.exe raii.vcxproj /t:Build /p:Configuration=Debug /p:Platform=x64 /nologo /verbosity:minimal 실행.
- 강사 실행·검증: build/vs/x64/Debug에서 .\raii.exe 실행 후 Get-Content -LiteralPath note.txt -Encoding UTF8 -Raw로 내용을 확인함. Visual Studio 실행 작업 폴더도 출력 폴더로 지정함.
- 결과: 빌드 성공, 경고 출력 없음. 콘솔 result: 0, 실행 종료 코드 0, note.txt의 Learning RAII 한 줄을 확인함. 이는 강사 검증이며 사용자 실행으로 기록하지 않음. 기존 사용자 소스는 수정하지 않음.

- 현재 상태: S5 확인 완료, R1 실행과 설명 대기. 파일 정리 규칙은 예제 제공만으로 습득 처리하지 않음. 기존 미확인 실습과 전체 회차 체크박스는 유지함.
